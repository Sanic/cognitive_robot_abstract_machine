## What works

CLI entry: `refine.py`. Commands: init, align, view, accept, serve, demo.
Python implementation: `scan_refiner/`; page template and controls: its `web/`.

Frozen root-frame body meshes, independent visual/collision roles, saved preview
records, input hashes/scale, versioned schema, deterministic spatial sampling,
automatic upright registration with alternatives, explicit acceptance, portable
viewer, candidate switching and scan-to-triangle heatmap are implemented.

The browser is currently a read-only review page; run registration through CLI.
No E57 indexing, progressive browser loading, exact raw evidence access, model
editing or source writing yet. Those are the next increments, not implied by
the preview's point count or viewer controls.

## Remember for continuation

See ROADMAP.md: automatic registration and good inspection first; repeated scans
are deferred. **Remind the user to add missing-object fitting** (box, cylinder,
simple object from a selected scan region) after the initial refinement workflow.

Registration currently assumes common upright Z axes and uses coarse binary XY
correlation followed by robust yaw/XYZ fitting. It does not detect gravity/floor,
keep registration history or resolve all partial-overlap ambiguities. Several
initial hypotheses can converge to similar final transforms. No score is a
calibrated confidence value. Geometry snapshot metadata currently omits the
semantic graph. Existing Python providers can still supply their full worlds
when collecting geometry; preserve their construction for future semantic work.
